the flaky test that fought its own controller

github.com/ovn-kubernetes/ovn-kubernetes · PR #6863

🐣 first — what is an "orphan node" E2E test?

EgressIP assigns source IPs to pods leaving the cluster.
If a node loses its host-cidrs annotation, it's "orphaned."
The E2E test verifies the controller skips orphan nodes
instead of crashing or blocking all other assignments.

🐛 one problem found

1. 🔴 test vs. controller race — the test can't win
The test deleted the host-cidrs annotation from a real node.
But ovnkube-node watches netlink address events and
immediately restores the annotation.

The test and the controller were fighting over the same field.
Sometimes the test won. Sometimes the controller won.
classic flake — the test fought a controller it couldn't beat

💭 what changed?

before fix

pick a real node
↓
delete host-cidrs annotation
↓
ovnkube-node: "hey! put it back"
↓
test checks annotation gone
↓
sometimes yes, sometimes no 🎲

after fix

create a synthetic Node object
↓
no ovnkube-node running on it
↓
nobody restores the annotation
↓
test owns the state completely
↓
deterministic ✓

💡 the rule

never mutate state that a controller is also managing.
If you poke a field and a controller restores it,
you've built a race, not a test.

Instead, create state the controller can't touch —
a synthetic object with no agent behind it.
