the error that fell through

github.com/k8snetworkplumbingwg/whereabouts · PR #748

🐣 first — what is Whereabouts?

Whereabouts is a CNI IPAM plugin for Kubernetes.
It tracks which IP addresses are assigned to which pods.
Two custom resources keep the books:
• IPPool — the allocation bitmap (which IPs are taken)
• ORIP — cross-range reservation (for overlapping subnets)

🐛 three problems found

1. 🔴 pool.Update fails → ORIP created anyway
When pool.Update() returns a permanent error,
execution falls through to create an ORIP record.
IPPool says "not allocated" but ORIP says "reserved" → drift

2. retries exhausted → still falls through
All temporary-error retries consumed, no successful write,
but the code kept going as if allocation succeeded.

3. overlapping range conflicts exhaust retries silently
Every candidate IP already reserved by another pod.
Retry loop exits with no error — ORIP created for an IP
that was never written to the IPPool.

💭 what changed?

before fix

pool.Update() fails
↓
error ignored / retries gone
↓
falls through to ORIP update
↓
ORIP created without IPPool ✗
↓
records diverge silently 💀

after fix

pool.Update() fails
↓
poolUpdateSucceeded = false
↓
return error immediately
↓
ORIP update never reached
↓
consistent state ✓

💡 the rule

when two records must stay in sync, gate the second on the first.
If step A fails, step B must not run.
A retry loop that exits without error isn't "success" —
it's "gave up quietly." Track whether the write actually landed.
